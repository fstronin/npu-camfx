# Руководство пользователя

## 1. Что происходит при включении

`npu-effects.service` запускает `npueffectsd`, который держит
`/dev/video60` и отдаёт туда **чёрный кадр**, пока камера не нужна.
Физический сенсор при этом выключен (LED не горит). Когда приложение
открывает `/dev/video60`, демон запускает libcamera; кадры идут в тот же
виртуальный поток.

Когда Zoom, GNOME Camera или другое приложение открывает `/dev/video60`
(напрямую или через PipeWire), daemon видит **чужой** PID с открытым
устройством, ставит `active=true`; UI-сервис опрашивает состояние и
показывает иконку.

## 2. Иконка в верхней панели

- Иконка: `camera-web-symbolic`.
- Появляется, когда камера реально стартовала (через ~0.6–1 с после
  открытия vcam); при простое скрывается (`PASSIVE`).
- `GetState().active` равен `true` только пока физическая камера
  стримит; именно по нему UI показывает иконку. Если приложение уже
  читает vcam, а иконки нет, проверьте `GetState` и журнал
  `npu-effects-ui.service`.
- Светодиод камеры горит только в это время; после закрытия приложения
  гаснет через ~1 с.
- Если включён `hidetopbar@mathieu.bidon.ca`, панель скрыта — подведите
  курсор к верхнему краю экрана.
- Клик по иконке открывает меню.

## 3. Меню

```
Эффекты камеры (NPU)
────────────────────
[превью] Без эффектов
[превью] Размытие фона
[превью] Украшательства
[превью] ✓ Размытие + украшательства
────────────────────
Сила украшательств ▸ Лёгкая / Средняя / Сильная
Обновить превью
Показать превью крупно
```

- Превью — 160×90 PNG, сгенерированные из последнего кадра тем же
  процессором, что и видео.
- Галочка отмечает текущий режим.
- Превью обновляются:
  - при переходе камеры в активное состояние;
  - раз в 5 секунд, пока камера активна;
  - по пункту «Обновить превью»;
  - после смены режима.
- «Сила украшательств» — подменю: Лёгкая (0.4), Средняя (0.7), Сильная
  (1.0). Выбор силы сразу включает «Украшательства» (или
  «Размытие + украшательства», если уже включено размытие).
- «Показать превью крупно» открывает окно 2×2 (320×180) с кнопками
  «Выбрать»; это удобнее для сравнения перед звонком. Окно обновляется
  тем же `RefreshPreviews`.
- При первом открытии камеры приложение может показать ~0.6 с чёрного
  кадра — это placeholder, пока libcamera запускается; затем идёт видео.

## 4. Режимы

| Режим | Когда использовать |
|---|---|
| Без эффектов | обычный звонок; применяется только gamma 0.85 |
| Размытие фона | фон мешает/отвлекает; человек остаётся резким |
| Украшательства | сглаживание кожи без глаз/рта; фон не меняется |
| Размытие + украшательства | оба эффекта |

### Стабильность края

Маска стабилизируется медианой 3×3 и EMA: в покое край почти не
мерцает, при жестах/резком движении фильтр быстро адаптируется (возможен
небольшой лаг в 1–2 кадра). Превью не влияют на live-историю маски.

### Украшательства

Эффект работает по коже лба/щёк: bilateral + мягкий glow + подъём
яркости. Борода, очки, волосы и губы исключаются геометрией лица и
35 точками. «Сильная» (1.0) заметно выравнивает кожу, «Лёгкая» (0.4) —
почти незаметна. По умолчанию — «Средняя» (0.7).

### Сила эффектов

По умолчанию:

- `gamma = 0.85` (GStreamer-соглашение: выход = вход^(1/gamma), т.е.
  midtones темнее);
- `blur-strength = 0.6`;
- `smooth-strength = 0.7` (Средняя).

Изменить без UI:

```bash
gdbus call --session --dest ru.fstronin.NpuEffects \
  --object-path /ru/fstronin/NpuEffects \
  --method ru.fstronin.NpuEffects.SetBlurStrength 0.8

gdbus call --session --dest ru.fstronin.NpuEffects \
  --object-path /ru/fstronin/NpuEffects \
  --method ru.fstronin.NpuEffects.SetSmoothStrength 0.3

gdbus call --session --dest ru.fstronin.NpuEffects \
  --object-path /ru/fstronin/NpuEffects \
  --method ru.fstronin.NpuEffects.SetGamma 0.78
```

Значения применяются к следующему кадру.

## 5. Проверка состояния

```bash
gdbus call --session --dest ru.fstronin.NpuEffects \
  --object-path /ru/fstronin/NpuEffects \
  --method ru.fstronin.NpuEffects.GetState
```

Пример:

```
({'active': <true>, 'mode': <'blur-beauty'>,
  'gamma': <0.85>, 'blur': <0.6>, 'smooth': <0.7>,
  'device': <'NPU'>},)
```

## 6. Превью и файлы

Daemon пишет превью в:

```
/run/user/<uid>/npu-effects/preview-off.png
/run/user/<uid>/npu-effects/preview-blur.png
/run/user/<uid>/npu-effects/preview-beauty.png
/run/user/<uid>/npu-effects/preview-blur-beauty.png
```

Их можно открыть вручную; UI читает те же файлы.

## 7. Логи

```bash
journalctl --user -u npu-effects.service -f
journalctl --user -u npu-effects-ui.service -f
```

Типичные сообщения:

- `[npueffects] segmenter on NPU at 256x256` — модель загружена.
- `[npueffects] face analysis on NPU` — детектор/лендмарки.
- `[npueffectsd] pipeline camera (mode=..., device=NPU)` — пайплайн поднят.
- `libayatana-appindicator is deprecated` — предупреждение библиотеки,
  не ошибка.

## 8. Переключение обратно на relayd

```bash
cd /path/to/npu-camfx
./scripts/restore-relayd.sh
```

Скрипт выключит новые юниты, снимет маску с `gc2607-vcam.service` и
вернёт старый relayd с `cam-preset.service`. Вернуться:

```bash
./scripts/use-effects-vcam.sh
```

## 9. Частые проблемы

| Симптом | Проверка/решение |
|---|---|
| Нет иконки | камера не открыта (`GetState().active=false`) — это норма; если камера уже читается, проверьте `GetState` и `journalctl --user -u npu-effects-ui.service`; проверьте `hidetopbar` |
| Иконка есть, превью пустые | подождите 5 с или нажмите «Обновить превью»; проверьте права на `/run/user/<uid>/npu-effects` |
| Камера занята | `fuser -v /dev/video60`; не запущены ли relayd и daemon одновременно |
| Чёрные поля по бокам | в пайплайне не должно быть `videoscale`; libcamera должна отдавать 1280×720 |
| Нет эффекта | `GetState().mode`; журнал daemon; модель в `~/npu-models` |
| Низкий fps | `./scripts/bench.sh`; проверьте нагрузку CPU/питание |
| Ошибка модели | `journalctl --user -u npu-effects.service`; модели скачать заново |

## 10. Приватность

- Модели и кадры обрабатываются локально.
- D-Bus-сервис доступен процессам вашей сессии; отдельной авторизации нет.
- Превью лежат в `/run/user/<uid>` (tmpfs, исчезают после перезагрузки).

# ADR 0003 — D-Bus methods + polling

**Статус:** принято, 2026-10-19.

## Контекст

UI нужны: текущий режим, активность камеры, смена режима, генерация превью.
Можно сделать D-Bus properties + signals, но это требует GObject-свойств,
отслеживания владельца, обработки `PropertiesChanged` и синхронизации
состояния при рестарте daemon.

## Решение

Только **методы**:

- `SetMode`, `SetGamma`, `SetBlurStrength`, `SetSmoothStrength`;
- `GetState() → a{sv}`;
- `RefreshPreviews() → a{ss}`;
- `Quit`.

UI опрашивает `GetState` раз в секунду; при переходе `active` false→true
сразу генерирует превью и далее раз в 5 с. Никаких signals/properties.

## Последствия

- Латентность появления иконки ≤1 с; смена режима — сразу.
- Нет проблем с устаревшими подписками после рестарта daemon.
- Простой контракт, легко тестируется `gdbus`.
- `a{sv}`/`a{ss}` не требуют JSON-парсера.

## Альтернативы

- Properties + signals: сложнее, не даёт выигрыша при 1 Гц.
- gRPC/Unix socket: лишняя зависимость.
- GSettings: не для рантайм-состояния и превью.
